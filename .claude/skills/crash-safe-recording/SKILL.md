# Крэш-безопасная потоковая запись

> Требование: запись пишется потоком на диск, переживает рестарт/краш, и приложение само
> диагностирует, если запись не пошла. Ниже — проверенный подход и главные гатчи.

## Главная гатча
`AVAssetWriter` даёт **валидный файл только после `finishWriting()`**. При `kill -9`/рестарте
незакрытый файл обычно **битый** (не дописан заголовок/индекс). Значит, нельзя писать всю встречу
в один незакрытый файл — потеряешь всё.

## Решение: сегментирование
- Писать **короткими сегментами по ~10–15 с** (`SegmentWriter`): каждый сегмент — отдельный
  `AVAssetWriter`, который по истечении интервала **финализируется** и становится валидным файлом.
  Файлы: `system/0000.wav`, `system/0001.wav`, …, аналогично `mic/`.
- Так жёсткий сбой теряет **максимум последний незакрытый сегмент**.
- Частый flush; не держать всю запись в памяти.
- (Альтернатива, если контейнер капризит: писать **raw PCM** посегментно — raw-append крэш-безопасен
  сам по себе — и собирать WAV на финализации/восстановлении.)

## Маркер сессии
`session.json` в папке записи: `status` (`recording`/`done`/`recovered`), `started_at`, конфиг,
счётчик сегментов. Обновлять по ходу. Чистый стоп → `done` + склейка. `recording` на запуске =
запись прервана нештатно.

## Восстановление на старте (`RecoveryManager`)
На запуске приложения просканировать архив; для каждой папки с `status=recording`:
1. Взять валидные сегменты по порядку (последний, если битый/недописан — **отбросить, не падать**).
2. Склеить через `ffmpeg` concat → `system.wav`/`mic.wav`, микс → `combined.wav`.
3. `status=recovered`, уведомить пользователя.
Логику выбора сегментов для склейки вынести в **чистую функцию** и покрыть юнит-тестом.

## Самодиагностика старта (`SelfCheck`) + watchdog
- После старта в первые ~2 с проверить, что **данные реально идут** (растёт размер текущего
  сегмента / приходят буферы). Если нет — определить причину и **вылечить**:
  - нет Screen Recording (`CGPreflightScreenCaptureAccess`==false) → запрос/подсказка;
  - `SCStream` не поднялся / ошибка делегата → рестарт (2–3 попытки);
  - нет аудио-девайса → понятная ошибка.
- **Никогда** не показывать «recording», если данные не пишутся.
- **Watchdog** во время записи: буферы встали на N с → пометить, перезапустить стрим, сохранив
  уже записанные сегменты; не помогло → ошибка в UI.

## ffmpeg
- Конкатенация сегментов: `ffmpeg -f concat -safe 0 -i list.txt -c copy system.wav`
- Микс двух дорожек: `ffmpeg -i system.wav -i mic.wav -filter_complex amix=inputs=2:duration=longest combined.wav`
- Аргументы команд выносить в чистые функции → покрывать юнит-тестами.
